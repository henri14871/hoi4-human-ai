# Technical notes

How `version.dll` works, and the reverse-engineering behind it. For install and usage, see the
[main README](../README.md).

## Engine map

Everything below was found by static analysis of `hoi4.exe` 1.19.4.1. The offsets are RVAs in that
build. The DLL does **not** hard-code them: it finds them at startup by byte signature and MSVC
RTTI, so small patches shouldn't break it. If anything fails to match, it logs the failure and
leaves the game vanilla.

| What | Where | How it was found |
|---|---|---|
| `g_humanAI` byte | `+0x33ddaa9` | Handler of the `human_ai` console command (`!flag`, prints "Human AI is now ON/OFF") |
| `IsAITag(gamestate, &tag)` | `+0x1f8460` | `is_ai` trigger (`CIsAITrigger`, vtable slot 22): `IsAITag(...) \|\| g_humanAI` |
| gamestate pointer | `+0x33dd6b0` | First argument to `IsAITag` |
| `CCountry` tag | `CCountry+0x8` | `IsAIControlled(country)` at `+0x747ab0` passes `&country->+8` |
| `CCountryAI::GetCountry` | `+0x2c02b0` | Called at the top of the module updates on `module->[+8]->vfunc1()` |
| AI modules | RTTI | `CAIModule` subclasses: `CAIForeignMinister`, `CAIInteriorMinister`, `CAIMilitaryMinister`, `CAIPoliticalMinister`, `CAIGeneral`, `CAIBaseGeneral`, `CAIVolunteerGeneral`, `CCryptologyAI` |
| Update slots | `CAIModule` vtable 11–17 | Profiler labels `Module.Update`, `.UpdateAIRoles`, `.HourlyUpdate`, `.DailyUpdate`, `.WeeklyUpdate`, `.MonthlyUpdate`, `.YearlyUpdate` |
| Theatre update | `+0x1145890` | Called by `CAIMilitaryMinister` Hourly (13) and Daily (14) updates; runs the air and naval sub-AIs |
| Air sub-AI | minister `+0x138` | `+0x135da00` air bases, `+0x13542f0` mission planning (reads `AI_FRACTION_OF_FIGHTERS_RESERVED_FOR_INTERCEPTION`), `+0x1146c10`/`+0x1146530` mission scoring |
| Naval sub-AI | minister `+0x5a0` | `+0x1afbd40` naval objectives (reads `AI_NAVAL_GOALS_UPDATE_FREQUENCY_DAYS`), `+0x1b5d10` gate in front of the rest of the naval block |

Confirmed in game (1.19.4.1): every module resolves through `owner = CCountryAI` to its country,
and human countries are told apart correctly (`ai_country=0`).

## Runtime

1. `proxy.cpp` forwards all 17 `version.dll` exports to System32 and starts an init thread, but
   only inside `hoi4.exe`. The launcher and `dowser.exe` load it too.
2. Turning on any area sets `g_humanAI` (the same switch as the `human_ai` console command), so
   the engine runs the AI for human countries.
3. Every update slot of every module class is redirected through `HaiThunk` (`asm.asm`), which
   preserves the register arguments and calls `HaiShouldRun`. For an AI country it always runs the
   original. For a human country it runs only if that module's area is handed to the AI.
4. Land, air and navy are split like this:
   - **land** = `CAIGeneral`/`CAIBaseGeneral` (fronts, armies, army groups).
   - **air** and **navy** live inside `CAIMilitaryMinister`, so that minister runs when any of the
     three is on.
   - Six call sites in its theatre update are patched to gate air and navy individually. A skipped
     naval gate returns `false`, which skips the whole naval block.
   - If that signature ever stops matching, air and navy just follow the minister.

Other `g_humanAI` readers (35 in total) mostly suppress player popups, such as focus-complete,
tech-unlock and template notices, while human AI is on.

## In-game panel

The panel is plain HoI4 script, generated by `tools/gen_panel.py`:
- `interface/hai_panel.gui` has the layout.
- `common/scripted_guis/hai_panel.txt` has the buttons.
- `common/scripted_effects` and `common/on_actions` sync the panel when a save loads.

The buttons set global flags, which is how choices get saved per campaign, and run
`log = "HAI_CMD <area> <0|1>"`. The DLL tails `Documents\Paradox Interactive\Hearts of Iron
IV\logs\game.log` four times a second and applies those lines. It skips whatever is in the file at
launch, and starts over when the game truncates it. On load, `on_startup` re-sends every area from
the save's flags.

The scripted GUIs have `ai_enabled = { always = no }`. With `human_ai` on, the game treats the
player as AI, so the AI must never be able to press them.

## Config file

`human_ai.ini` sits in the game folder and is also written by the panel. The DLL re-reads it when
it changes.

```ini
[human_ai]
enabled=1      ; 0 = mod idle, game vanilla
foreign=0      ; 1 = the AI runs it for you
interior=0
political=0
land=0
air=0
navy=0
volunteers=0
cryptology=0
```

The DLL logs to `human_ai.log` in the game folder.

## Offline self-test

This maps `hoi4.exe` as an image (nothing runs) and does every lookup the real startup does,
without patching anything. Run it from the `native` folder after building, with your own game
path:

```bash
py -c "import ctypes;f=ctypes.WinDLL(r'build\version.dll').HaiSelfTest;f.argtypes=[ctypes.c_char_p]*2;print(f(rb'C:\Program Files (x86)\Steam\steamapps\common\Hearts of Iron IV\hoi4.exe',b'build'))"
```

`1` means pass. Details are in `build/human_ai.log`. Run it first after every game patch.

## Not verified yet

- **Exactly what each minister covers.** The area descriptions come from class names and the
  strings their code reaches.
- **How cleanly land, air and navy separate.** With only `air` or only `navy` on, the military
  minister still runs its other work for you: theatres, invasion planning, and two unlabelled calls
  (`+0x113fdd0`, `+0x113f680`). Naval invasions and transfers are planned by `CAIGeneral`. Air or
  naval orders issued from anywhere other than the six hooked sites are not gated.
- **Things outside the modules.** With `g_humanAI` on, the engine may also answer some prompts
  for you, such as event options and diplomatic replies.

## Analysis tools

`tools/` holds the Python scripts used to find all of this (`pip install pefile capstone`):
- `xref_string.py`, `xref_global.py`, `disasm.py`, `callees.py`
- `profiler_labels.py` lists profiler scope labels
- `reach.py` shows which labelled code a function or module reaches
- `owner.py` finds the RTTI class that owns a function, following chained unwind info
- `vtables.py` dumps vtables and shows which slots each class overrides

Set `HOI4_EXE` to point them at your game.
